# FinanceHarness：金融深度研究智能体的时间、证据与评估契约

> **阅读结论**：FinanceHarness 的真正贡献不在于又增加了一组金融工具，而在于把金融研究最容易被忽略的三件事绑定成同一份契约：**在当时能看到什么、每个判断据何而来、如何在事后检验这个判断**。这使“写一篇像研究报告的文本”变成了一个可以受约束、可复现、可比较的智能体任务。[^financeharness]

## 1. 先界定问题：金融深度研究不是“更长的问答”

金融研究报告通常要回答的并非一个静态事实，而是一条带有时间方向的论证链。例如，分析师在某个时点判断一家半导体公司的评级时，需要同时处理历史财报、同行竞争、供应链、估值、宏观环境和未来需求。报告的价值不只在于罗列资料，更在于它是否能在**信息尚不完整时**给出有依据、可被后来事实检验的判断。[^financeharness]

这和传统金融问答任务有本质差别。以 FinanceBench 为例，它提供公司公开文件上的问题、答案与证据片段，适合评估模型能否在限定材料中找对并回答事实；但它并不要求模型在一个历史截点前形成投资论点，再让未来事件检验论点。[^financebench] FinBen 则把金融能力扩展到信息抽取、问答、预测、风险管理与决策等 24 类任务，说明“金融能力”本身是多维的；不过，多项离散能力的高分仍不等于能完成一篇可审计的分析师式报告。[^finben]

可以把两类任务并列理解：

| 问题类型 | 典型输入 | 成功标准 | 最主要的失真风险 |
|---|---|---|---|
| 金融 QA | 财报或已知材料 + 明确问题 | 找到正确事实并正确作答 | 幻觉、定位错误 |
| 金融预测 | 历史价格、文本或特征 | 对未来标签有统计预测力 | 前视偏差、非平稳性 |
| 金融深度研究 | 开放问题 + 截止日期 + 多源证据 | 形成有来源、有条件、有预测含义的研究论证 | 未来信息泄漏、无依据叙事、事后合理化 |

因此，本文读这篇论文时采用一个更严格的标准：它是否把金融研究中最重要的“时间边界”和“证据边界”写进了系统，而不是只把这些要求留给提示词中的一句提醒。

## 2. 论文的问题设定：把“知道未来”从系统中拿走

FinanceHarness 的配套基准 FinanceGym 为每道题指定一个截止日期 $\tau$。智能体在作答时只能访问发布时间不晚于 $\tau$ 的文档；截止日之后发生的事件不作为可检索证据，而是作为检验该报告前瞻判断的依据。论文将这两件事分成两类评分项：**截止日前证据综合**与**截止日后结果推断**。[^financeharness]

若以 $\mathcal{D}_{\leq \tau}$ 表示当时可获得的文档集合，研究报告可抽象为：

$$
r_\tau = \pi(q, \mathcal{D}_{\leq \tau}, \mathcal{T}),
$$

其中 $q$ 是研究问题，$\mathcal{T}$ 是搜索、阅读、计算等工具集合。真正要评估的不是 $r_\tau$ 在今天看来是否说中了多少结果，而是它能否在 $\mathcal{D}_{\leq \tau}$ 的约束下，完成如下两项任务：

$$
\text{Score}(r_\tau) = \lambda\, S_{\text{evidence}}(r_\tau) + (1-\lambda)\, S_{\text{outcome}}(r_\tau).
$$

前一项要求论据可追溯，后一项要求推断经得起后验事实检验。上式是对论文双层 rubric 的概念化表达，并非其训练目标的逐字复现；论文实际采用逐条 rubric 的 $0$ 到 $4$ 分评价，并把每个问题的 rubric 得分归一后平均。[^financeharness]

这套设定直接击中金融智能体最危险的失败模式：模型可以在今天检索到后来发生的并购、业绩或政策变化，再把这些信息伪装成“当时已可得出的高见”。在量化研究里，这叫前视偏差；在长篇研究报告里，它常常以更隐蔽的形式出现，即一段读起来合理、却不可能在当时写出的叙事。

## 3. FinanceGym：不是题库，而是一套研究情境生成机制

论文没有从固定主题里手工出题，而是先在带发布日期的公开网页语料中构建金融实体图，再从关系、时间叙事和正反向分歧中挖掘“情境”。每条图边保存实体、关系、局部上下文、来源 URL 与发布时间；在此之上，系统为情境选择截止日期、生成问题、投资论点与评分 rubric，再经过质量过滤、平衡和专家标注。[^financeharness]

这一设计值得注意，因为它试图让题目对应研究员会实际遇到的结构，而不是孤立的名词解释。论文将情境来源概括为三类：

1. **跨类别关联**：例如企业、商品、政策和产业链事件之间的多跳关系。
2. **时间叙事**：围绕高关联实体追踪事件如何展开。
3. **分歧情境**：例如评级上调与下调、业绩超预期与不及预期所形成的张力。

最终 FinanceGym 包含 400 道专家标注问题、2,464 条 rubric 项，平均每题 6.16 条；题目在主题、行业、推理类型与 12 个截止日期桶之间做平衡。论文报告专家质量审核通过率为 82%，这说明数据质量控制被纳入了基准构建，而非事后抽查。[^financeharness]

这里的核心不是“图谱一定更聪明”，而是**题目、证据、截止日与评分依据来自同一数据生成过程**。如果问题来自一个语料快照，证据来自另一个检索系统，评分又由没有证据上下文的评委完成，那么系统很难分清：模型究竟是找到了正确资料、进行了有效推理，还是只是写出一段讨好的金融语言。

## 4. FinanceHarness：所谓 harness，到底约束了什么

在这篇论文中，harness 不是单个模型，也不等同于 agent prompt；它是一层围绕模型的可执行基础设施，负责工具表面、运行循环、工作流技能、输出格式、恢复机制和评估连接。模型可以替换，但研究环境与评分契约保持一致。[^financeharness]

论文的实现可按五层理解：

```text
研究问题与截止日
  -> PIT 搜索与文档阅读
  -> 编排器：计划、调度、格式与预算控制
  -> 金融工具与可复用工作流：数据、计算、估值、可比公司、风险、情景分析
  -> 带编号引用的报告 + grounding review
  -> rubric judge：证据充分性与后验结果分别评分
```

### 4.1 环境层：把时间过滤做成检索接口的属性

论文以超过一亿篇、带发布日期的网页文章构建内部语料，用 Qwen3-Embedding-4B 生成向量，并以 FAISS 建立检索索引。关键不在向量模型本身，而在服务端执行的规则：搜索结果必须满足 $\text{date}(d) \leq \tau$，智能体也不能绕过接口访问实时网页。[^financeharness]

这比“请不要使用未来信息”的软约束强得多。RAG 的基本思想是把外部文档作为生成条件，从而为知识密集任务提供可检索证据；FinanceHarness 则进一步把**何时可检索**定义为环境状态的一部分。[^rag] 对金融研究而言，发布日期不是普通元数据，而是决定一个结论是否可交易、可复验的变量。

### 4.2 运行时层：限制模型，而不是假定模型会自律

核心运行时管理有界 agent loop、工具 schema 验证、分层工具加载、模式切换、错误恢复与上下文预算。工具分为始终加载的核心检索/阅读动作、按需展开的金融工具目录，以及可接入 MCP 或 CLI 的扩展层。[^financeharness]

这与 ReAct 的思想一脉相承：语言模型不只输出最终答案，而是在“推理 - 行动 - 观察”的循环中调用外部环境。[^react] 但 FinanceHarness 的增量在于，行动空间并不只是搜索；它还要求每次研究轨迹遵守同一个时间、来源、引用和预算契约。换言之，ReAct 提供通用交互范式，harness 决定这个范式在金融场景里哪些行动是合法、可复查且成本可控的。

### 4.3 工作流层：把领域知识放在可调用技能中

论文给出 research、analytical 与 automatic 三种模式：前者偏向网页证据收集，后者偏向数据与计算，automatic 让模型选择。更重要的是，工作流技能不是写死的 agent 角色，而是按描述路由的可复用规范；它们声明所需工具和专业上下文，可以用于估值、可比公司、风险分析或情景推演。[^financeharness]

这里和金融多智能体交易系统形成了有益对照。TradingAgents 将基本面、情绪、技术、风险等角色分离，再通过多空辩论和交易者综合信息形成决策。[^tradingagents] 两类系统都在引入领域分工；差别在于，TradingAgents 的输出是交易决策，而 FinanceHarness 的一等产物是**带来源、可审查的研究报告**。前者更接近“谁来判断”，后者更强调“判断链条能否被复盘”。

### 4.4 证据层：引用不是排版，而是系统状态

论文的编排器会从已访问来源中组织编号引用；若草稿遗漏引用，系统可补做引用整理，并以 grounding review 要求模型弱化或归因那些无法连接到已读来源或工具输出的表述。它还会在昂贵读取前检查文档 ID，避免无效访问。论文报告，移除该 guardrail 后访问错误率从 2.1% 上升到 39.4%，尽管最终得分变化不大，但轨迹成本明显上升。[^financeharness]

这告诉我们一个容易被忽略的事实：**引用完整性和运行成本是同一个工程问题的两个侧面。**如果系统不知道一条结论来自何处，它也无法有效判断是否应重读、补证、停止搜索或降低措辞强度。对个人研究笔记同样如此：引用应附着在具体主张旁，而不是在文末堆一个“参考资料”清单。

## 5. 评估与训练共用契约：为什么这比“再训一个 agent”更重要

FinanceHarness 最有启发性的设计，是令 rollout 和 evaluation 共用搜索 API、文档访问规则、引用要求和 rubric 信号。若更换底座模型，只改变可学习模型层，不改变工具和评分环境。论文将这种一致性视为减少 tool-distribution shift 的关键。[^financeharness]

这是一个很朴素却常被忽略的因果问题。设训练时工具分布为 $p_{\text{train}}(o \mid a)$，评测时为 $p_{\text{test}}(o \mid a)$；同一个工具调用 $a$ 在两种环境返回的观察 $o$ 若差异很大，模型学到的策略就未必能迁移。金融研究尤其敏感，因为实时网页、付费终端、公司文件和内部数据库的覆盖、时效、格式都不同。

论文的实验也提供了一个警告：在同一 PIT 检索环境下，原本针对实时网页工具训练的开源深度研究模型会面对工具分布转移，其分数并不必然优于通用底座配合恰当脚手架。这个结论不能被泛化为“训练无用”，但说明**环境接口本身就是策略的一部分**。[^financeharness]

在训练部分，作者使用与 FinanceGym 独立的 172 条机器筛选实例进行 GRPO。奖励由 rubric 风格评分（权重 0.6）和报告连贯性、grounding、轨迹质量的 LLM judge（权重 0.4）组成。固定 Qwen3.6-27B 底座时，搜索工具基线、朴素 harness、完整 harness 与 GRPO 微调版本的总体分数依次为 25.3%、29.6%、32.4% 和 32.8%。[^financeharness]

这组消融的正确读法并不是“GRPO 没用”，而是：在该设置里，**先把环境、工具链和评估写对**带来的增益，大于后续强化训练带来的边际增益。对于搭建个人金融研究系统的人，这个优先级很有现实意义。

## 6. 怎样读实验：进步存在，但前瞻推理仍是瓶颈

论文在 17 个系统上评测 FinanceGym。所有系统总体得分都低于 40%。在统一的 Qwen3.6-27B 底座上，完整 FinanceHarness 的总分为 32.4%，高于只有搜索工具的 25.3%；其截止日前得分为 45.7%，截止日后得分只有 11.8%。[^financeharness]

最重要的信号是这个巨大的前后差距。检索到历史证据、写出看似严谨的解释，与基于这些证据预测之后会发生什么，是不同难度层次的任务。前瞻部分还同时混入了：基准题目的内在不确定性、金融事件的多因性、公开语料覆盖不足，以及 rubric 是否能完整表达一个投资判断等问题。

因此，不能把 11.8% 简单解释成“模型不会预测”。更稳妥的解释是：在严格禁止未来信息的条件下，现有系统仍难以稳定地将历史证据转化为可检验的前瞻论证。这个发现和金融领域既有基准的动机相呼应：FinanceBench 的人工审阅显示，即使接入检索，模型仍会在金融问题上频繁回答错误、拒答或幻觉；FinBen 也将预测、风险和决策视为不能被单一 QA 指标覆盖的独立维度。[^financebench][^finben]

## 7. 与相关工作的关系：它补上的到底是哪一块

| 工作 | 主要对象 | 核心评价单位 | FinanceHarness 补充的维度 |
|---|---|---|---|
| RAG | 知识密集生成 | 答案是否由检索文档支撑 | 为检索增加逐题时间截断与金融研究情境。[^rag] |
| ReAct | 推理与工具调用 | 交互式任务完成 | 将金融工具、引用、预算与恢复策略做成运行时约束。[^react] |
| FinanceBench | 公司文件上的金融 QA | 答案与证据片段 | 从短答案推进到跨来源、带前瞻判断的长报告。[^financebench] |
| FinBen | 多维金融 LLM 能力 | 36 数据集、24 任务 | 以“研究报告”作为多项能力的联合输出。[^finben] |
| TradingAgents | 交易团队式多智能体 | 交易表现与风险指标 | 转向研究过程的时间一致性与可审计证据链。[^tradingagents] |
| FinanceHarness / FinanceGym | 金融深度研究智能体 | PIT 受限报告的 rubric 得分 | 将环境、执行、证据和评估统一为同一契约。[^financeharness] |

这张表也揭示出一个边界：FinanceHarness 不是替代量化回测、资产定价检验或投资组合优化的系统。它更像研究流程中的“上游研究员”：帮助把异构公开信息整理为可追踪的论点、假设和风险情景。将报告进一步转成交易信号，仍需经历数据可得性审计、明确的标签定义、滚动样本外验证、成本与容量分析。

## 8. 批判性阅读：论文尚未解决什么

### 8.1 点时可得，不等于经济上可得

论文的 PIT 规则以网页文章发布时间为边界，这是必要且强的第一步；但金融数据还有更多时间语义：财报何时披露、公告何时发布、修订数据何时可见、新闻何时被市场消化、付费数据源在当时是否有权限。网页发布日期只能近似一部分信息集。论文也明确承认内部语料主要是 2025 年英文公开网页，非英文、付费专业数据和结构化文件覆盖有限。[^financeharness]

### 8.2 可验证 rubric，不等于唯一正确的投资论点

将评分拆成明确条目能提高一致性，但优秀投资研究常存在等价的替代路径：不同证据组合可能支持不同的、但同样合理的条件性结论。论文用专家验证、证据关联和五级锚点缓解这一问题，却无法完全消除 rubric 设计本身的主观性。因而，分数应被理解为“在该研究契约下的完成度”，而非策略真实 Alpha 的估计。

### 8.3 结果验证会引入幸存叙事风险

用截止日后的事实判断报告是否有前瞻性很自然，但也可能让评估偏好那些事后最显眼的事件。一个严谨的报告若正确指出多种情景并标注概率，却没有押中最终发生的单一路径，可能低估其研究价值。更进一步的设计应要求报告显式给出条件、反例和可观测触发器，再按情景校准度而不是单一结果命中来评分。

### 8.4 工具一致性是优点，也可能形成封闭世界

固定工具接口使比较更公平，却可能奖励最适配该接口的策略。论文已经观察到实时网页训练的模型在 corpus-backed 工具上存在迁移问题。下一步不只是让模型适应更多工具，更应把跨工具稳健性作为单独评测轴：同一研究计划在不同合规数据源、不同检索器和不同文档格式下是否仍能保留关键证据链。

## 9. 对个人研究工作流的启示

这篇论文最适合迁移到个人主页和研究笔记中的，不是复杂的 agent 框架，而是四个纪律：

1. **给每个判断标时间。** 写“截至某日，已知证据支持什么”，不要把后来结果倒灌进当时的研究结论。
2. **让引用贴着主张。** 一段中的事实、推断和不确定性应能对应到具体来源；这也是本博客右侧边注的用途。
3. **区分证据与预测。** 用“事实”“解释”“情景”“判断”四种句式写作，避免将推测伪装为资料。
4. **记录研究轨迹。** 对重要结论保存检索词、数据版本、截止日期、失败路径与最终采用理由；这比只保留一篇漂亮的结论性文章更可复现。

如果把它放入量化研究链条，FinanceHarness 更接近“产生和审计研究假设”的环节，而非“直接决定持仓”的环节：

```text
带时间截断的研究问题
  -> 来源与证据链
  -> 条件化投资论点 / 风险情景
  -> 可检验的因子、事件或标签假设
  -> 样本外验证与组合构建
  -> 交易成本、风险与上线监控
```

这也为后续研究留下了一个具体问题：能否把报告中的实体关系、情景触发条件和置信边界，结构化地转成事件因子或研究特征，同时保持从最终信号回溯到原始证据与当时信息集的能力？如果做不到这一步，智能体写得再像分析师，也仍只是一个高流畅度的信息整理器。

## 10. 总结

FinanceHarness 重新定义了金融深度研究智能体的优先级：先解决信息是否属于当时、证据是否能回溯、评价是否和执行环境一致，再讨论模型参数规模、提示词花样或强化学习算法。论文的实验没有证明系统已经具备可靠投资预测能力，反而清楚暴露了前瞻推理仍然困难；但它提供了一套值得复用的研究基础设施思想。

对金融 AI 而言，可信度不是由报告篇幅、引用数量或单次回测曲线决定的，而是由一条可复查的链条决定：**何时知道什么，基于什么作出什么条件性的判断，后来又如何被检验。**
